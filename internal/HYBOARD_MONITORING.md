# Мониторинг HyBoard

Мониторинг добавлен в административную панель как отдельный контур наблюдения. Он не находится на пути VPN-трафика, не проксирует соединения и не меняет рабочие настройки Hysteria2.

## Что отображается

- по каждому ключу: онлайн-состояние, число соединений, накопленные скачивание/отдача, текущая скорость;
- по VPS: приблизительная загрузка CPU, load average, RAM, диск, входящая и исходящая скорость;
- состояния `hysteria`, `hyboard`, `nginx` и `x-ui`;
- срок действия TLS-сертификата Hysteria2 и использование обновляемой ссылки Certbot;
- суммарные ошибки приёма UDP в ядре;
- последние 60 минутных выборок на графике;
- результаты независимых внешних проверок;
- активные предупреждения.

Колонки «трафик сегодня» нет. Накопленные счётчики переживают перезапуск Hysteria: если исходный счётчик сбросился, HyBoard продолжает увеличивать собственный итог.

История хранится в `/var/lib/hyboard/hyboard.db` 30 дней. Панель не запрашивает `/dump/streams`, не сохраняет домены, IP назначения, URL или содержимое трафика.

## Фоновый сбор

`hyboard-monitor.timer` запускает `hyboard-monitor.service` раз в минуту. Веб-панель лишь читает готовые значения из SQLite; кнопка обновления может выполнить внеочередной сбор. Сборщик работает от пользователя `hyboard`, а узкий root-broker разрешает только предопределённое чтение системных показателей.

Проверка:

```bash
systemctl status hyboard-monitor.timer
systemctl start hyboard-monitor.service
journalctl -u hyboard-monitor.service -n 30 --no-pager
```

## Трафик пользователей Hysteria2

HyBoard использует официальный локальный Traffic Stats API Hysteria2: `GET /traffic` и `GET /online`. Клиент жёстко принимает только `http://127.0.0.1`, `http://[::1]` или `http://localhost`; передать ему внешний URL нельзя.

Интеграция выключена по умолчанию, потому что её автоматическое включение потребовало бы изменить рабочую конфигурацию Hysteria2. После отдельного резервного копирования и проверки синтаксиса в конфигурации Hysteria можно определить loopback listener и секрет, а в `/etc/hyboard/hyboard.env` задать:

```dotenv
HYBOARD_TRAFFIC_STATS_ENABLED=1
HYBOARD_TRAFFIC_STATS_URL=http://127.0.0.1:9999
HYBOARD_TRAFFIC_STATS_SECRET=REPLACE_WITH_RANDOM_SECRET
```

Секрет не коммитится. Перед изменением Hysteria необходимо сверить синтаксис с версией установленного сервера, сохранить рабочий конфиг и подготовить откат. Код HyBoard сам Hysteria не перезапускает.

Если API выключен или недоступен, управление ключами продолжает работать; интерфейс показывает информационное предупреждение, а не выдуманные нулевые данные.

## Предупреждения

Встроенные правила создают предупреждение при следующих состояниях:

- Hysteria не активна или UDP/443 не слушается;
- TLS-сертификат Hysteria истёк, истечёт менее чем через 72 часа или подключён как статическая копия вместо обновляемой ссылки;
- диск заполнен на 80% (warning) или 90% (critical);
- RAM занята на 90% и более;
- обнаружены ошибки приёма UDP;
- источник статистики трафика недоступен;
- внешний наблюдатель сообщил об ошибке или перестал присылать данные.

Telegram получает только новые проблемы, изменения их текста/уровня и сообщение о восстановлении. Одинаковое предупреждение каждую минуту не дублируется.

Для short-lived IP-сертификата Hysteria должна читать сертификат и ключ прямо из
`/etc/letsencrypt/live/<certificate-name>/`. Копия файла в `/root` или `/etc/hysteria`
не обновится при очередном запуске Certbot. Hysteria читает указанные файлы при новом
TLS-handshake, поэтому после штатного продления перезапуск сервиса не требуется.

Настройка:

```dotenv
HYBOARD_TELEGRAM_BOT_TOKEN=REPLACE_WITH_BOT_TOKEN
HYBOARD_TELEGRAM_CHAT_ID=REPLACE_WITH_CHAT_ID
```

После изменения env достаточно перезапустить панель и один раз запустить сборщик:

```bash
systemctl restart hyboard.service
systemctl start hyboard-monitor.service
```

## Обнаружение возможной блокировки

Франкфуртский VPS не может самостоятельно доказать, что трафик блокируется в конкретной российской мобильной сети. Для этого нужен независимый наблюдатель внутри проверяемой сети: телефон, ноутбук или отдельный узел, который реально пытается подключиться через VPN и отправляет результат в HyBoard.

API отчёта:

```text
POST /api/probes/{name}
Authorization: Bearer <HYBOARD_PROBE_TOKEN>
Content-Type: application/json

{"ok":true,"latency_ms":118,"network":"mobile-mts","detail":""}
```

Токен должен содержать не менее 24 случайных символов:

```dotenv
HYBOARD_PROBE_TOKEN=REPLACE_WITH_LONG_RANDOM_TOKEN
HYBOARD_PROBE_STALE_SECONDS=900
```

Если внешний путь к панели защищён mTLS, наблюдателю также нужен собственный клиентский сертификат. Репозиторий не создаёт, не копирует и не изменяет `.p12`; это отдельная операция управления доступом. До появления хотя бы одного независимого наблюдателя панель честно сообщает, что внешних данных нет, и не называет обычный серверный сбой «блокировкой».

## Границы безопасности

- новые TCP/UDP-порты установщик не открывает;
- настройки Nginx, mTLS и `.p12` не меняются;
- Hysteria, Xray, WireGuard, FreeTurn, firewall и маршрутизация не меняются;
- Telegram-токен, probe token и секрет Stats API находятся только в root-owned env-файле;
- `/dump/streams` намеренно не используется;
- мониторинг можно полностью отключить, остановив `hyboard-monitor.timer`; работа VPN от этого не зависит.
